# Konomi Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local-first anime list where adding is instant, scores come from comparisons, and a taste model trained on 57M MAL ratings recommends, predicts and visualises the user's taste.

**Architecture:** Offline Python pipeline builds the catalog (AOD + Kaggle + AniList) and trains models on the GPU, exporting small artifacts. FastAPI serves auth, lists, rating maths and taste inference (numpy, CPU) over Postgres+pgvector. React/Vite SPA does search locally in a Web Worker and renders the galaxy in WebGL.

**Tech Stack:** Python 3.13 (uv venvs), PyTorch cu128, polars, scikit-learn, umap-learn, sentence-transformers; FastAPI, SQLAlchemy 2, Alembic, psycopg 3, pgvector, argon2-cffi, Pillow; React 18 + TS + Vite, React Router, TanStack Query, MiniSearch, Motion, GSAP, three / @react-three/fiber, Lenis; Playwright; Docker (pgvector/pgvector:pg18, axllent/mailpit).

**Spec:** `docs/superpowers/specs/2026-11-01-konomi-design.md`

## Global Constraints

- Dev DB only: API reads `KONOMI_DATABASE_URL` (default `postgresql+psycopg://konomi:konomi@localhost:5433/konomi`). Nothing reads `DATABASE_URL`/`DATABASE_URL_POOLED` (Neon) tonight.
- Ports: Postgres 5433, Mailpit SMTP 1025 / UI+API 8025, API 8000, web 5173 (Vite proxies `/api` and `/og` to 8000).
- Adult filter: drop any title with AOD tag `hentai`, AniList `isAdult`, or Kaggle `Rating` starting `Rx`, from catalog and training data. Ecchi stays.
- Score scale 1.0–10.0, one decimal (familiar from MAL, comparable to community scores; the decimal gives 1–100-like resolution without the user ever choosing it). User never types a number.
- Feeling tiers → non-overlapping bands: 5 "One of my favourites" 9.0–10.0 · 4 "Loved it" 8.0–8.9 · 3 "Liked it" 6.5–7.9 · 2 "It was okay" 5.0–6.4 · 1 "Didn't like it" 1.0–4.9. Within a band: n=1 → band midpoint; n>1 → lo + (hi−lo)·r/(n−1), r = rank from worst (0) to best (n−1), so the user's very best is exactly 10.0.
- Training is never force-stopped by time: runs until early stopping on validation; owner said no time limit.
- Model's prediction is revealed only after the user answers.
- Raw ratings and `data/` never committed; `.env` never committed.
- Commits: short one-line message, no body, no trailer. Push to `origin master` after each task.
- Every screen designed for 360–430 px phones, 1280, 1440–1536, 1920, 2560 widths.
- E2E (Playwright) run only at Task 15 / major milestones. Unit tests only for score maths, auth, model eval.
- Footer credits: anime-offline-database (ODbL), MyAnimeList data via Kaggle, AniList.

## Review Focus

1. Search for romaji/English/abbreviations/typos (`shingeki`, `aot`, `frieren`, `kimetsu no yaiba`, `steins gate`) → top hit is the main TV series, not a special/recap. Pinned in Task 7.
2. User with 0–2 rated titles opens recs/predict/DNA → popularity-aware fallback, never NaN/500. Pinned in Task 10.
3. Post-2020 anime (no MAL id, bridge embedding only) in a user's list → included in fold-in and predictable. Pinned in Task 10.
4. OTP abuse: wrong code ×5, expired code, resend spam → locked/expired/429, never verifies. Pinned in Task 5.
5. Private profile fetched logged-out, including `/og/u/<name>.png` and `/api/u/<name>/match` → 404 "private", no data. Pinned in Task 13.

Artifacts contract (`data/build/artifacts/`, produced by Task 9, consumed by Tasks 4 & 10):
- `items.parquet`: `aod_key:str, has_cf:bool, emb:list[f32] (d), x,y,z:f32, cluster:i16`
- `multvae.npz`: encoder weights `W1,b1,Wmu,bmu`, `item_order` (aod_keys of CF items), `d`
- `ease_topk.npz` (only if EASE ships): CSR `data,indices,indptr` over `item_order`
- `axes.json`: `[{id, neg_label, pos_label, item_loadings_key}]`; `clusters.json`: `[{id,label,tags[]}]`
- `calibration.json`: global mapping model-score-percentile → rating, used when a user has < 5 scored titles
- `manifest.json`: `{model:"multvae"|"ease"|"ensemble", d, version, metrics}`

`aod_key` = `mal:<id>` if MAL source exists, else `anilist:<id>`, else first source URL. It is the join key everywhere outside the DB; DB `anime.id` is a serial.

### Task 8: Rating system

**Files:** `api/konomi_api/rating/{score,select,routes}.py`, `api/tests/test_score.py`, `web/src/features/rate/*`.
**Produces:** `fit_scores(entries:list[Entry], duels:list[Duel]) -> dict[anime_id, float]`; `next_insertion_duel(user, anime_id) -> (a,b)|None`; `next_session_question(user) -> Question`.

Score maths (`score.py`): Bradley–Terry strengths per user over all their duels (MM iterations, ties = half win, weak prior 0); within each tier, order items by strength; map to the band with the Global Constraints formula; round 1 decimal. Untiered items: score null.
Selection (`select.py`): insertion = binary search of the new item against the same-tier ordering, ≤ 6 duels, stop on "too close". Session = (1) completed titles without tier → ask tier, (2) adjacent same-tier pairs with fewest direct comparisons, (3) facet questions for top titles missing facets.

**Files:** `api/konomi_api/taste/{engine,routes}.py`, `api/tests/test_taste.py`.
**Produces:** `TasteEngine.user_vector(entries) -> np.ndarray|None`, `.recommend(entries, k, filters) -> list[Rec(anime_id, score, because:[anime_id,anime_id])]`, `.predict(entries, anime_id) -> float|None`, `.dna(entries) -> list[Axis(id, neg, pos, value)]`, `.match(a_entries, b_entries) -> {percent, agree:[...], fight:[...]}`.
